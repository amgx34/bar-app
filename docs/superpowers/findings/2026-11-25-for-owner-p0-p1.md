## Update 2026-11-25: P1 #2 (payroll tips exceed Z tips) is not cash tips and not a seed artifact

Checked after the owner asked whether cash tips explain the gap. They do not.

- The demo seed writes `cash_tips: 0` on every night (`lib/demo/seed.ts` around line 288). The only cash entry in the dev project is the walker's own $12.34 test.
- The seed's per-server tips sum to the Z total: for example night offset 13, 396 + 360 + 320 = 1076 = `cc_tips`. So the individual bartender's tips are already inside the Z total.
- In `app/(app)/app/payroll/actions.ts`, `dailyTips` is the full Z total (`cash_tips + cc_tips`, less removals). The barback and opener cuts and the hours-weighted pool are all computed from that full figure, and the pool is shared among `pool`-mode staff. Then, further down, the per-server loop adds `serverEntry.tipsPaidOut` to each `individual`-mode employee **on top** of that. `sales_pct` mode adds `share * dailyTips` on top in the same way.
- Numbers match exactly: 2026-11-19 Z total $1,212 + Danny's $384 = $1,596, the figure the payroll header showed. November: gap $1,792 = Danny Rivera's total tips.

So the pool is not reduced by what an `individual` or `sales_pct` server keeps, and the code's own comment ("the night still reconciles against the Z report") does not hold when such an employee works. **Nothing was changed.** This is tips and payroll money, so it needs the owner's decision first:

1. Is the Z `cc_tips` total meant to include individual servers' tips in real 2Touch data (as the seed assumes)? If yes, the pool should be `dailyTips` minus the individual and sales-percentage amounts, and a test should assert that the night's allocations sum to the Z total. If no (individual tips are reported separately from `cc_tips`), the seed is wrong and the code is right.
2. A real bar with an individual-mode bartender may already have been overpaid. Worth checking one real night against the Z report by hand before deciding.
