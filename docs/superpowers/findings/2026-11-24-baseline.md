# Baseline — 2026-11-24

## Test suite

**Before:** `npm test` — 54 of 54 files failed to load, `TypeError: Cannot read
properties of undefined (reading 'config')`, no tests ran.

**Cause:** not the repo. VS Code opens terminals with a lowercase drive letter
(`c:\Users\...`). Vitest then loads two copies of itself, one under `c:` and one
under `C:` once the resolver canonicalises the path, so a test file's `describe`
talks to a runner that was never initialised. A trivial one-line test fails the
same way; the same test passes from `C:\...`. Ruled out on the way: duplicate
vitest copies, vitest/vite peer mismatch (4.1.11 and 4.1.12 on vite 7 and 8),
`resolve.tsconfigPaths`, `resolve.preserveSymlinks`, the vitest cache, and the
pool type. Setting `root` in the config does not help, because the vitest process
is already running from the lowercase path before any config is read.

**Fix:** `npm test` and `npm run test:watch` now go through
`scripts/dev/run-vitest.mjs`, which relaunches vitest from an upper-case drive
letter (`upperDriveLetter` in `scripts/dev/drive-letter.mjs`, 5 tests).
`vitest.config.mts` also now includes `scripts/**/*.test.ts`. A bare
`npx vitest` from a lowercase shell still fails; `AGENTS.md` says so.

**After:** 55 files, 938 tests, all pass. No money test failed, so nothing was
triaged or escalated.
