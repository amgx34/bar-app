This guide covers everything needed to connect a bar's POS system to Rail.
Follow only the section that matches the bar's POS system.

  Section A — Prerequisites (ALL installs, do this first)
  Section B — Clover POS
  Section C — Toast POS
  Section D — 2TouchPOS (SQL Agent)
  Section E — Verify everything is working

Estimated time per install:
  Clover    →  15 minutes
  Toast     →  10 minutes
  2TouchPOS →  10 minutes (one file, double-click, answer a few prompts)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
SECTION A — PREREQUISITES (do this before ANY POS setup)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  A1. Log into Vercel
      ─────────────────
      URL:  https://vercel.com
      Navigate to the Rail project → Settings → Environment Variables

  A2. Confirm these variables are set (they should already be there):
      ──────────────────────────────────────────────────────────────────
      NEXT_PUBLIC_SUPABASE_URL          (Supabase project URL)
      NEXT_PUBLIC_SUPABASE_ANON_KEY     (Supabase anon key)
      SUPABASE_SERVICE_ROLE_KEY         (Supabase service role key)
      GROQ_API_KEY                      (AI parsing — needed for 2Touch email)
      GMAIL_USER                        (railpossystems@gmail.com)
      GMAIL_APP_PASSWORD                (ebhljbnzmbmcnyly)

  A3. Log into Rail as the bar owner
      ─────────────────────────────────
      URL:  https://bar-app-drab.vercel.app/login
      Once logged in, go to Settings → POS Integration
      You will configure the POS connection from this page.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
SECTION B — CLOVER POS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Clover uses OAuth — the bar owner clicks a button and approves access.
  No software needs to be installed on any local machine.

  B1. Confirm environment variables are set in Vercel
      ──────────────────────────────────────────────────
      Check that these exist in Vercel → Settings → Environment Variables:

        CLOVER_CLIENT_ID       3102ffdc-b7b7-dff8-cd34-36f1dba1afc0
        CLOVER_REDIRECT_URI    https://bar-app-drab.vercel.app/api/clover/callback
        CLOVER_SANDBOX         false

      If any are missing, add them now and click Save, then
      Deployments → Redeploy (to pick up new env vars).

  B2. Register the redirect URI in the Clover Developer Dashboard
      ─────────────────────────────────────────────────────────────
      URL:  https://www.clover.com/developers
      → Your Apps → select the app (ID: 3102ffdc-...)
      → Edit → REST Configuration section
      → Find "Site URL" or "OAuth Redirect URL"
      → Enter exactly:
            https://bar-app-drab.vercel.app/api/clover/callback
      → Save

  B3. Connect Clover in Rail
      ──────────────────────────
      In Rail → Settings → POS Integration → Clover section
      → Click "Authorize with Clover"
      → You are redirected to Clover's website
      → Log in with the bar's Clover account
      → Click "Allow"
      → You are returned to Rail with "Clover connected" confirmation

  B4. Sync data
      ────────────
      In Rail → Settings → POS Integration → Clover section:
      → Click "Sync Inventory"  (imports Clover item catalog)
      → Click "Sync Sales (7 days)"  (imports last 7 nights of sales)

      Both buttons show a success toast when done.

  ✓  Clover setup complete.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
SECTION C — TOAST POS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Toast uses API keys — no OAuth redirect. The bar generates credentials
  from their own Toast Web account and enters them into Rail directly.

  C1. Generate Toast API credentials
      ────────────────────────────────
      The bar owner needs to do this from their Toast account:

      1. Go to  https://pos.toasttab.com  and log in
      2. Navigate to:  Integrations → Toast API access → Manage credentials
      3. Click:  Create new credentials → Standard API
      4. Enter a name:  Rail
      5. Select these scopes (permissions):
           ☑  Orders
           ☑  Labor
           ☑  Menu
      6. Select the location (the bar's location)
      7. Click Confirm
      8. Copy the three values shown:
           Client ID       →  save this
           Client Secret   →  save this (shown ONCE — copy it now)
           Restaurant GUID →  save this

      NOTE: The Client Secret is only shown once.
      If it was missed, delete and recreate the credentials.

  C2. Enter credentials in Rail
      ───────────────────────────
      In Rail → Settings → POS Integration → Toast section:
      → Enter Client ID
      → Enter Client Secret
      → Enter Restaurant GUID
      → Click "Connect Toast"

      Rail will test the connection. If it succeeds you'll see
      "Toast connected successfully!"

      If it fails:
        - Double check the credentials (no extra spaces)
        - Confirm the bar has Toast Restaurant Management Suite Essentials
          or higher (API access is not available on the base plan)

  C3. Sync data
      ────────────
      In Rail → Settings → POS Integration → Toast section:
      → Click "Sync Sales (7 days)"   →  imports last 7 nights to Dashboard
      → Click "Sync Menu / Inventory" →  imports menu items to Inventory
      → Click "Sync Shifts (7 days)"  →  imports employee hours to Payroll

      OR in Rail → Payroll → Import tab, you will see a Toast Sync panel
      with the same three sync buttons.

  ✓  Toast setup complete.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
SECTION D — 2TOUCHPOS (SQL AGENT)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  2Touch has no cloud API, so a small Windows Service runs on the POS machine,
  reads the local SQL Server every 5 minutes, and pushes to Rail.

  THIS SECTION WAS REWRITTEN. The old steps — enable Mixed Authentication,
  start SQL Server Browser, restart SQL Server, install Node.js, hand-edit a
  config file, create a scheduled task — are all gone. The .NET agent connects
  over shared memory, so there is no port to find and no Browser service to
  start, and it installs itself.

  You will need:
    - Physical or remote access to the 2Touch Windows POS machine
    - Administrator on that machine
    - ONE file:  rail-2touch-agent.exe
    - The pairing code from Rail (step D1)

  Nothing else. No Node.js. No .NET runtime. No SQL script. No second file:
  the agent's default configuration is embedded in the exe.

  ─────────────────────────────────────────────────────────────────────────
  D1. In Rail — activate 2TouchPOS and copy the pairing code
  ─────────────────────────────────────────────────────────────────────────

      Rail → Settings → POS Integration → 2TouchPOS:

      1. (Optional) In "2Touch Report Sender Email", enter the address that
         2Touch emails reports from. That is the email fallback for bars not
         running the agent; leave it blank if you are installing the agent.
      2. Click Activate.
      3. Click "Copy pairing code".

      The code is one line beginning RAIL1- and carries the org id, this bar's
      unique token, and the Rail URL. It is per-bar — never reuse one bar's
      code on another bar's machine.

      Get it onto the POS box however is easiest (email it to yourself, a
      remote-desktop clipboard, a text file on a USB stick). You will paste it
      once; nothing is typed by hand.

  ─────────────────────────────────────────────────────────────────────────
  D2. On the POS machine — copy the agent and double-click it
  ─────────────────────────────────────────────────────────────────────────

      Copy rail-2touch-agent.exe anywhere on the machine (the Desktop is
      fine — setup relocates it to C:\rail-agent\ itself).

      Double-click it. Windows will ask for Administrator — click Yes.

      A console window opens and runs twelve stages. Answer the prompts:

        [2/12]  Paste the pairing code from D1.
        [4/12]  Pick the SQL Server instance, if there is more than one.
        [5/12]  Pick the database — it selects TwoTouch automatically when
                there is one.
        [7/12]  Confirm the schema mapping. See D3.
        [8/12]  Check the preview looks like this bar's real trade.

      Everything else runs unattended.

  ─────────────────────────────────────────────────────────────────────────
  D3. Confirming the schema (stage 7)
  ─────────────────────────────────────────────────────────────────────────

      TwoTouch databases differ between versions and sites, so the agent does
      not assume any table names. It reads the whole database and, for each of
      the three feeds, offers the five relations that best fit, with a proposed
      column for every field it needs.

      For each feed you can:
        - press Enter to accept the top suggestion
        - type a number to pick a different relation
        - answer "n" to the "Use this mapping?" prompt and override one column
        - type 0 to skip the feed, if this bar genuinely has no such data

      Any column marked "← guess: name gives no clue, check this" was chosen on
      data type alone. Look at those before accepting.

      Each accepted mapping is immediately run against the database. If the
      query fails, the error and the SQL are printed and you go back to the
      mapping — a wrong guess is caught here, not weeks later.

  ─────────────────────────────────────────────────────────────────────────
  D4. Watching the data land (stages 10-12)
  ─────────────────────────────────────────────────────────────────────────

      Setup installs the service, starts it, and then runs one real sync in
      front of you. Do not leave the site until you have seen:

        ✓ Rail accepted the data — Z:7 EW:28 Audit:42

      The final screen prints the install path, the service name
      (Rail2TouchSync), where the logs go, the uninstall command, and the
      confirmed schema mapping as JSON.

      COPY THAT JSON into the repo issue for this bar. Real mappings from real
      boxes are how the agent's guesses get better.

  ─────────────────────────────────────────────────────────────────────────
  D5. If something goes wrong
  ─────────────────────────────────────────────────────────────────────────

      Every stage prints a diagnosis rather than a stack trace. The ones you
      are most likely to hit:

      "token must be 64 hex characters, got 61"
          The paste was truncated. Copy the whole line again.

      "Rail rejected the token (401)"
          The code belongs to a different bar, or the token was regenerated in
          Rail after the code was copied. Re-copy from Settings.

      "Rail rejected the org (400)"
          2TouchPOS was never activated for this bar. Do D1 step 2.

      "Could not reach https://…"
          The box needs OUTBOUND HTTPS only. No inbound rule, no port forward,
          no static IP. Check the site's firewall or proxy.

      "No SQL Server instance is registered on this machine"
          Almost always the wrong machine. The agent must run on the box that
          hosts the TwoTouch database.

      "This server is set to Windows Authentication only"
          Setup normally avoids this entirely by granting NT AUTHORITY\SYSTEM
          read access and running the service under Windows auth. You only see
          this if the account you ran setup as is not a SQL sysadmin. Re-run
          setup as an account that is. Do NOT enable Mixed Mode on a live POS
          box to work around it — that needs a SQL Server restart.

      "The service did not start"
          The last five Event Log entries are printed underneath. They are also
          in Event Viewer → Windows Logs → Application, source Rail2TouchSync.

  ─────────────────────────────────────────────────────────────────────────
  D6. Re-running, and uninstalling
  ─────────────────────────────────────────────────────────────────────────

      To fix a bad schema mapping, or to move a bar to a different Rail org,
      just run setup again. It stops the service, rewrites the configuration,
      and restarts. There is no uninstall-first step.

      To remove it, from an elevated Command Prompt:

        C:\rail-agent\rail-2touch-agent.exe --uninstall

      That stops and deletes the service and leaves C:\rail-agent\ in place.
      Delete the folder afterwards if you want the configuration gone too.

  ✓  2TouchPOS setup complete.

SECTION E — VERIFY EVERYTHING IS WORKING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  After completing the POS setup, confirm these work in Rail:

  E1. Dashboard
      ──────────
      URL:  https://bar-app-drab.vercel.app/app/dashboard
      ✓ Inventory Value shows a dollar amount (not $0)
      ✓ Last Night shows a sales figure
      ✓ Revenue Trend chart has bars

  E2. Inventory
      ──────────
      URL:  https://bar-app-drab.vercel.app/app/inventory
      ✓ Items are listed with names and categories
      ✓ Items show cost_price and par_level values
        (if empty, the bar needs to fill these in manually)

  E3. Payroll → Import
      ─────────────────
      URL:  https://bar-app-drab.vercel.app/app/payroll?tab=import
      ✓ For Toast: "Toast POS Sync" card appears at the top
      ✓ For 2Touch: 'sc query Rail2TouchSync' shows RUNNING, and the Dashboard
          shows data for today

  E4. POS Connection badge
      ──────────────────────
      In the top navigation bar of Rail, you should see a green
      pulsing dot with the POS name (Clover / Toast) when connected.

  │ Data                │ Clover       │ Toast        │ 2TouchPOS          │
  ├─────────────────────┼──────────────┼──────────────┼────────────────────┤
  │ Daily sales + tips  │ Manual sync  │ Manual sync  │ Auto every 5 min   │
  │ Inventory items     │ Manual sync  │ Manual sync  │ Auto every 5 min   │
  │ Employee shifts     │ —            │ Manual sync  │ Auto every 5 min   │
  │ Per-server tips     │ —            │ —            │ Auto every 5 min   │
  │ Item audit by day   │ —            │ —            │ Auto every 5 min   │
  └─────────────────────┴──────────────┴──────────────┴────────────────────┘

  "Manual sync" = click the sync button in Rail → Settings → POS Integration
  "Auto" = runs on schedule, no action needed after initial setup
